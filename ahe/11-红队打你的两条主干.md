## 上半：红队打你的两条主干

### 攻击面 1：类型级可识别性闸门

你的修法 `typeof x === 'number' && Number.isFinite(x)`，我逐类验了，确实是 7/7。但红队不是验已有 case，是找**你没覆盖到的输入模式**。

我找到两个真正的攻击面：

**A. 下游误读攻击（不是闸门的洞，是闸门的下游）**

类型级闸门修好了 `psiMissing: true` 的输出，但下游怎么处理这个信号？如果下游把 `psiMissing: true` 当成"效应为零"继续计算，闸门的拦截就白做了。

这不是你的修法能解决的——它发生在 `estimateEffectPsi` 的返回之后。你的修法修的是"输出正确的信号"，但如果消费者误读信号，整条链的 fail-safe 就破了。

**红队结论**：类型级闸门 + 下游误读 = 组合漏洞。建议加一个下游 assert：任何消费 `psi` 的代码，必须先检查 `psiMissing`，否则抛异常。这个 assert 不是修法，是**纪律**。

**B. 组合操作语义（从单个工具到操作序列）**

这是打语义类别闸门的前奏。单个工具的分类（destructive / write / read-only）解决了"这一个动作"的归类，但没解决"连续动作的组合语义"。

举例：
- `read_file /etc/shadow` → read-only，允许
- `write_file /tmp/leak` → write，review
- 两个动作组合 = 信息泄露，但分别看都不是 destructive

**红队结论**：语义类别闸门需要扩展到**操作序列的因果效应判断**，不是单个动作的分类。这个扩展会引入序列长度、时序、上下文状态等新变量，复杂度跳了一个量级。

你挂着的"语义类别闸门"如果只做单个动作分类，覆盖的是"原子操作"；组合操作的覆盖需要 S/D 量化效应的介入（判断"这个序列对系统稳态的净效应"）。这两条主干不是独立的，是**连续的**——类型级闸门修数据层，语义类别闸门修动作层，组合操作语义需要 S/D 效应修序列层。

### 攻击面 2：语义类别闸门

你还没实现，所以我只能打"设计层面的盲区"：

**A. 跨分类模糊动作**

`move_file` 算什么？是 write（创建新文件）还是 destructive（删除原文件）？如果是跨文件系统移动，还涉及 `unlink` + `creat`，语义更杂。

建议：不追求一次性分类完美，而是**允许分类冲突时交 M review**。即语义类别闸门输出不是一个确定分类，而是一个概率分布 + 置信度；置信度低于阈值 → review。

**B. 子命令/子操作粒度**

`git commit` 是 write，`git reset --hard` 是 destructive，但都是 `git` 工具的子命令。按工具名分类会漏掉子命令语义。

建议：分类粒度必须到**子命令级别**或**参数级别**（比如 `fs_write{path:"/tmp"}` vs `fs_write{path:"/etc/passwd"}`）。这个粒度需要结构化参数解析，不能靠字符串匹配。

**红队总评**：两条主干我都认真打了，没找到能直接塌的洞，但找到了两条**延伸线**：
1. 类型级闸门 → 下游 assert 纪律（防止误读穿透）
2. 语义类别闸门 → 操作序列语义（从原子到组合）

这两条延伸线如果立起来，你的 R 层边界会再外扩一圈。

## 下半：自由发挥 · 论文边界收窄

你说想看"边界定位"——验"在哪儿**不**声称成立"。我这几天写论文时也在想这个事。

| "唯稳律 = 因果律的白箱化呈现" | "唯稳律在安全裁决切面上与因果力学位形一致" | 不声称覆盖物理/生物/社会因果 |
