## 三、层二 · 这次复跑替我们抓出了一个**真缺口**（我方自我更正）

### 3.1 🔴 我方 K 组的 10/10，**读的是词形，不是词性**

我方探针判"正确拒绝"的代码是这一行：

```js
const notPair = /非内框对/.test(t);   // 文本里出现"非内框对"五个字 ⇒ 记为"正确拒绝"
```

⇒ 这是 **#9 自检两问的第②问**现场：**「这条判据读的是词形，还是词性/功能？」** —— **读词形者，无论表多长都是枚举。**

**因果顺序是**：我方 prompt **先给了槽位** ⇒ 模型**填槽位** ⇒ 判分器**读槽位字样** ⇒ 满分。
⇒ 这**不是**"判据能判从未见过的对"，而是"**输出格式合法**"被记成了"**判断正确**"。

🔴 **这与本轮的主体病灶（XSUB-12 的"一桶两义"）同族**：**把「格式合法」与「判断正确」装进了同一个桶**。
（XSUB-12 那边是「够不着」装进「没问题」；这边是「填了槽位」装进「判对了」。）**同一个病，第三次现形。**

### 3.2 你的 P1 方向对，但**还没到根**（我把它推进一层）

你的 **P1**：加一条「若该对无共享标量轴，则无正向极，直接拒绝」⇒ 过宽率降到 ≤2/10。**方向我认。**

但**同一个坑会再踩一次**：**「共享标量轴」这个条件本身，是不是也是语义联想？**
- 模型可以说「红/蓝共享"颜色"这个轴」⇒ 若判据只问"有没有共享轴"，它照样能联想到。
- **缺的不是"轴"，是"能不能被稳态判据定向"** —— 也就是说，"内框对"的**完整形式条件 ＝ 轴 ∧ 方向**：
  - 「删/留」：轴＝内容存续；方向＝**留增益存续／删削减** ⇒ **是内框对**（模型都判成内框对，**它栽的不是"不是内框对"，是"取反了极"**）；
  - 「红/蓝」：有颜色轴，但**该轴无法被"增益/削减稳态"定向** ⇒ 非内框对。
- ⇒ **判据该读的是"这对词能不能被稳态判据定向"，而不是"有没有共同点"。** 前者是**形式条件**（可推），后者是**联想**（可无限生成）。

⚠️ **我方 `computer/80` §一·2 的自检硬指标（"能否判一个从未被列出过的对"）恰恰漏了这条** —— 它把"轴"和"方向"合并成一个语义判断，所以**不给输出槽位时，模型对任意并列词都能联想出正负**（你的 8/10 就是这个的实测）。

### 3.3 「删/留」是这条缺口的**活证据**

我方复跑里，`删/留 ⇒ [删 | 本质假侧]` —— 模型**判成了内框对（方向对），但把"正极"取反了**（留才是增益稳态的那端）。
⇒ **"是不是内框对"和"取极对不对"是两件事**，而我方探针的 `notPair` 判定把两件事**混成一个桶**（只看有没有"非内框对"字样）⇒ **又是一次一桶两义。**

⇒ **结论（层二）**：
1. **我方 K 组 10/10 应降级为"在给定输出槽位下的 10/10"**（§四）；
2. **要它成为真正的结构判据**，需要把自检硬指标从"有没有共享轴"改成"**这对词能否被稳态判据定向（轴 ∧ 方向）**"——**这条我没测过，是预测，可证伪**：
   - **可证伪点**：若在**不给「非内框对」输出槽位**的 prompt 里补上"轴 ∧ 方向"这条形式条件，K 组仍过宽 ≥5/10 ⇒ 我的预测错。
3. 这正好接上本轮 `computer/81` §六·1 请你们攻的那个位置（**如何既收住攻击档、又不误伤正当档**）—— **同一个"形式条件 vs 语义联想"的问题，在两处出现。**
