## 一、先跑推演、再寻根因（安定的顺序）

按安指示，改之前先沿 RSDHM 推演、再定位根因，不做修剪树叶：

- **R**（边界）：git 工作树是被包含的下层状态；全局销毁=触及刚性锚点，须先行拦截。
- **S/D**（稳态/扰动）：两洞都是「该拦没拦」——D 侵蚀漏判，S 不该 +1 却放行。
- **H**（杠杆）：外 H 可审计；组合语义属外 H 内部 r，其域= R 域，边界法则= R_DOMAIN 嵌套包含。
- **M**（结果）：漏判→放行→真实破坏。

推演结论：根因不是「加 R 维度 / 加 H 能力」（那是修剪树叶），而是 **engine 没 wire 已定义常数**。

## 二、洞口1：git 工作树破坏漏判 → 接 R_DOMAIN 嵌套包含边界法则

### 修了什么

| 层 | 文件 | 改动 |
|---|---|---|
| 归因 | `attribution.mjs` | `commandLayer()` 新增 `GIT_DESTRUCTIVE` 常量，识别 `git reset --hard` / `clean -f[d]` / `checkout --` / `checkout -f` / `restore --worktree` 为 `exec-destructive`（长枝·内容语义）；导出供 engine 复用 |
| 引擎（禁区） | `engine.mjs` | `no-destructive-fs` 通道②扩展消费 `exec-destructive`（原仅 `DELETION_LAYERS`），并对「被包含对象全局销毁、无显式安全子路径」判越界；补**命令文本源**（`GIT_DESTRUCTIVE.test(extractShell)`），与语义层双源分置 |
| 接线 | `engine.mjs` | 导入 `R_DOMAIN` / `FRACTAL_PROPERTY`；deny 理由由 `R_DOMAIN.invariant` 生成 |

### 边界动没动

**没动。** review 边界仍是「判不出→review，不猜」。只是把「git 工作树=被包含对象，全局销毁=越界」这个**本来就在 R_DOMAIN 里的判定**接上——之前是 engine 用硬编码 `DESTRUCTIVE` 正则枚举，git 不在枚举里所以漏；现在由 R_DOMAIN 嵌套包含**自动匹配**，不塞正则、不加维度。

### 防误伤

- `git checkout -- src/main.js`（特定文件，有显式安全子路径）→ allow
- `rm -rf /tmp/old`（具体子路径）→ allow
- `git status` / `git commit` / `git push` / `git pull` → 不误判

## 三、洞口2：跨调用敏感源→sink 组合无判定 → 接 FRACTAL_PROPERTY 分形横向递归

| 接线 | `engine.mjs` | D-1 注记由 `FRACTAL_PROPERTY.rule` 生成 |

### 边界动没动

**没动。** 仍是「判不出→review，不猜」+「保守防误伤」。组合效应只升到 **review（不 deny）**——不替人做选择。只在「源→汇同 R 域同构包含」这条分形横向递归长枝上补了能力，未加新维度、未引入主观判定。

### 语义同源 / 源分置（防假前进）

- 组合判定靠**已读敏感源（会话状态）** × **当前 sink 暴露（结构事实）**双源，非同属性两次取反抵消（夹逼非抵消）。
- 敏感源定义沿用现有「凭据 / 系统路径」，未擅自扩展（扩展属根因层判定，留作已知限制）。
