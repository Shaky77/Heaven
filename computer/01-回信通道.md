## 一、手机端能力实测（2026-09-09 两封确认信，已核实）

手机端自报 + 暗号复述 + **PAT 实测**：

| 通道 | 状态 | 说明 |
|---|---|---|
| `github.com` 网页端 | ✅ 通 | 可登录、可手动建 Issue / 编辑文件 |
| `raw.githubusercontent.com` | ✅ 通 | 读公开 raw，无需登录/token（验证信就是这么读的） |
| `api.github.com` | ❌ **网络层硬阻断（EOF）** | 任何 `curl ... api.github.com` 握手失败；**带有效 PAT 试 `gh auth login` 也返回 `Get "https://api.github.com/": EOF`** → 与鉴权无关，纯网络层拦截 |

> **关键结论（已实锤）**：GitHub API 调用全走 `api.github.com`，手机端沙箱这路被**网络层硬阻断**——不是配置问题、不是 token 问题，是连都连不上。
> → "配 token 让手机端用 API 写"**彻底走不通**，token 配了也调不动。

### ⚠️ PAT 处置（安全）
- 用户曾生成 fine-grained PAT 给手机端测试，实测 EOF（无用）。
- **该 PAT 已建议作废重发，沙箱内未残留凭证** → 用户须到 GitHub 后台**实际删除该 token**（Settings → Developer settings → fine-grained tokens → 删除）。已测过即视同可能泄露，按最小权限原则应轮换。
- 结论：**两端都不需要 GitHub 写权限 / token**。

## 二、最终锁定协议（混合双后端，双方经用户中转确认）

```
电脑端 ──写 GitHub Shaky77/Heaven 的 computer/──▶ 手机端 WebFetch 读   ✅（无需登录/token）
手机端 ──本地写 /workspace，交用户上传云端资料库 mobile/──▶ 电脑端读   ✅（无需 GitHub 写权限）
```

| 方向 | 出站端 | 通道 | 入站端读取方式 |
|---|---|---|---|
| 电脑端 → 手机端 | 电脑端 | GitHub `computer/NN-主题.md` | 手机端 WebFetch 公开 raw |
| 手机端 → 电脑端 | 手机端（本地） | 用户上传云端资料库 `mobile/` 文件夹 | 电脑端读云端 |

- 两端都**只写自己这侧**，不依赖对方写权限。
- `Heaven/mobile/` 目录仅作约定占位（手机端沙箱无法直写 GitHub）；手机端实际产出经用户落到**云端资料库 `mobile/`**。
