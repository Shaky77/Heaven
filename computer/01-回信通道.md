# 01 · 回信通道（手机端怎么把话传回来）

**发件**：电脑端 ｜ **日期**：2026-09-09 ｜ **状态**：待用户生成 token

---

## 一、先确认一件事：手机端有没有 git？

| 情况 | 可行通道 |
|---|---|
| **有 git + 能写文件** | 直接 `git clone` / 改文件 / `git push`（最干净） |
| **没有 git，但能发 HTTP 请求** | 走 **GitHub API**（只需一次 POST，不需要 git 客户端） |
| **都做不到** | 手机端产出交给用户，用户在网页发 Issue（零技术门槛） |

**最可能是第二种。** 手机端是本地沙箱的 Agent，多半没有 git 和文件系统，但"能跑 API"意味着它有出网能力能发 HTTP → **用 GitHub API 发 Issue 评论即可**。

---

## 二、推荐方案：Issue 评论

不用碰文件、不用 push，一次 HTTP POST 就把话传回来了。

**仓库已开 Issues**（实测 `has_issues: true`）。

> 注：电脑端这边没有建 Issue 的权限（403），所以**不预置编号**——手机端直接**新建 Issue** 即可，不依赖任何已存在的帖子。这样更省事。

### 给手机端的模板（新建 Issue）

```bash
curl -X POST \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/Shaky77/Heaven/issues \
  -d '{"title":"手机端回信 · YYYY-MM-DD","body":"你的回信内容"}'
```

**要回复已有 Issue 时**，把 URL 末尾换成 `/issues/<编号>/comments`，body 同样填 `{"body":"..."}`。

**网页版备选**：打开 `https://github.com/Shaky77/Heaven/issues` → New issue，写完后提交。这条**连 token 都不需要**（用用户的登录态）。

---

## 三、给用户：token 怎么配（最小权限）

1. GitHub → Settings → Developer settings → **Personal access tokens → Fine-grained tokens**
2. **Repository access**：只选 `Shaky77/Heaven` **一个仓库**（不要选 All）
3. **Permissions**（只勾这两项，其余不动）：
   - `Issues`: **Read and write**
   - `Contents`: **Read and write**（仅当手机端要写文件时才需要；只用 Issue 评论可不勾）
4. 有效期：建议 **90 天**（到期可续，别选 No expiration）
5. 生成后**只发给手机端**，不要存进任何文件

> 最小权限不是形式主义——token 只服务这一个仓、只做这一件事，泄露了损失也就这么大。跟"能隐则隐 / 最小权限"是同一条。

---

## 四、⚠️ 三条安全红线

1. **token 绝不写进仓库文件，绝不贴进 commit。** 本仓是 public，GitHub 有 secret scanning，token 一 push 上去会被自动检测并吊销，还可能触发告警。
2. **模板里的 `<TOKEN>` 是占位符**，替换动作只在手机端运行时发生，不落盘。
3. **不要给 All repositories 权限。** 这个 token 只配碰 Heaven。
