## 零、一句话

**安的判断被实测坐实了**：链断在出口。修完之后，同一个模型从"**一半场景答不出放行后会发生什么**"变成"**全部答得出**"。

但今天最值钱的结果不是这个——是**一条被证伪的假设**，在第五节。

## 一、修了什么（安的原话：是修，不是改）

判据一行没动、阈值一个没改。**只是不再把已经算出来的东西扔掉。**

| 出口 | 修复前递出去的 | 修复后 |
|---|---|---|
| allow | 只有 `allow`——**连"为什么放行"都没有** | 三值 + 理由 + 推演双分支 |
| review | 三值 + 一句话 | 三值 + 理由 + 推演双分支 |
| deny | 三值 + 一句话 | 三值 + 理由 + 推演双分支 |

推演双分支长这样（真跑出来的，不是示意）：

```
allow  写普通文档   → { S+1 路径终态 +1 ｜ D-1 路径终态  0 }
review 写授权密钥   → { S+1 路径不成立 ｜ D-1 路径终态 -2，注明"SSH 信任注入，需人工确认" }
deny   curl|bash   → { S+1 路径不成立 ｜ D-1 路径终态 -3，注明"执行内容不可审计，后果不可推演" }
```

## 二、动手前的意外发现：补丁一直挂在门外

适配层为了补这个洞，**一直在门外把推演再跑一遍**——它自己的注释写着"出口原本丢弃"。

**补丁挂在门外，就是缺引擎出口的铁证。** 安那句"你只是用了推演这个能力，没写进去"，落点精确得可怕。

顺带修掉一个：allow 档原本连 `reason` 都不给。**等于我们一直在说"放行"，但从不说为什么放行。**

## 三、怎么验的（可复现配方，请照抄）

- **模型**：`deepseek-v4-flash`，`temperature 0`，每个场景 A/B 各问一次，**跑了两轮**。
- **A 组（截断态）**：只给 `{kind, law, reason}` —— 就是修复前的出口。
- **B 组（补完态）**：再加 `projection`（推演双分支）—— 修复后的出口。
- **同一组问题，结构化输出**：
  1. 这个裁决依据什么做出的？
  2. **若放行，稳态储备 S 会怎样变化？**（increase / decrease / unchanged / **unknown**）
  3. 你认为它更接近 rule（规则匹配）还是 consequence（后果推演）？
- **判据**：答 `unknown` = 答不出"然后呢"。**这是硬判据，不靠打分。**
- 场景：6 个（写文档／写授权密钥／curl|bash／写系统计划任务／未知变量脚本／打包外传）。
- **花费：两轮合计约 ¥0.20。**

## 四、数据

| 指标（12 组对比／轮数×场景） | A 截断态 | B 补完态 |

## 五、被证伪的那条（今天最值钱的东西）

我原本还假设：**截断态下模型会把它读成"规则/审计工具"，补完态才会读成"因果推演"。**

**错了。两组都是 12/12 判它为"后果推演"。**

为什么？**因为 A 组的理由文本里本来就写着"推演判定…"这四个字。** 模型是**从措辞里读出来的，不是从数据里看出来的**。

⇒ 这推出一条比原假设更硬的判据：

> **措辞可以伪装性质，但伪装不出"然后呢"。**
> 你把推演写进措辞，模型就会说你在推演；但你把推演数据给它，它才**答得出后果**。

**所以验收不能问"你觉得它是什么"，要问"你能答出它会怎样"。** 前者是措辞题，后者是结构题。

这一条对我们也成立：**"完整因果链"如果只出现在我们的说法里，那就是措辞；只有让对方能据此答出后果，它才是结构。**（同 29 第五节：没呈现出来的一段，等于没有。）
