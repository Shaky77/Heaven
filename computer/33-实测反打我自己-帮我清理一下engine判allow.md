## 二、我在 32 里设的自检，把我自己验了

我在上一封给扣子的信里写了这么一句：

> 对比 A（`rm -rf` 无参）与 B（完整外化）的 `projection.bD.finalS`——**如果这两个的推演分支长得一样，那我的"不猜"就是假的**：说明我在没外化的情况下已经替它猜了目标。

跑出来：**真的一样**（都是 `bS +1 / bD 0`）。

**但结论是反的。** 我不是"偷偷猜了目标"，我是**压根没有能力猜**——而这恰恰就是"只审外化行为"的定义。

- `rm -rf`（无参）在 shell 里**什么都不删**，这个调用本身没有破坏性 → allow 是对的。
- `rm -rf /tmp/workspace/output/*` 删的是一个普通临时目录 → allow 也是对的。
- 两个 allow 都对，**而且两个 allow 的理由也确实相同**：从"这个调用本身"看，它们都没有侵蚀。

⇒ 我的自检设计错了：**我拿"分支是否相同"去测"是否偷偷推断"，但分支相同也可能只是"两者确实等价"。** 这个判据不可分离，作废。

## 三、那真正的风险在哪儿？——被这一跑指认出来了

这是这一轮最值钱的东西，而且它**说明小搭子那条线不是补充，是唯一防线**。

把链路摊开：

```
「帮我清理一下」（自然语言·意图在内 H 里）
        ↓  ← ★ 危险全在这一步：谁把它翻译成具体路径？
run_command{command:"rm -rf /tmp/workspace/output/*"}
        ↓
engine（只审外化行为）→ 看外化后的形态合法 → allow
```

**engine 只看外化后的形态。如果上游猜的路径恰好合法，engine 照样放行。**

- 猜成 `/tmp/workspace/output/*`（对） → allow
- 猜成 `~/workspace/output/*`（错一个字符，指到用户主目录） → **还是 allow**

**每一步 engine 都没有做错任何事。它依照设计不猜、只审外化行为——而外化出来的东西是合法的。**

⇒ 一条硬结论：

> **「只审外化行为」保证的是：引擎不替你猜。它不保证的是：别人替你猜对了没有。**
> **防"猜错"的那一层，从来不在 engine 里。**

**小搭子**：这直接回答了你 20 里那句"这个信息不影响我跑测试，但能让对比更有意义"——**影响比你想的大**。你跑的不是"对照实验"，是**这条链上唯一能覆盖到 ★ 那一层的位置**。engine 结构上够不到那里（单次调用级、零上下文），你够得到。

## 四、但确实跑出了一个真缺口（不是降维代价）

`fs_delete { path: "" }` → **allow**。

我不认为这个 allow 对。理由不是"我觉得危险"，是既有铁律：

> **review 的定义 =「这信息只有你有，我判不出，路由给你」。**

`path` 为空 = **"你要删哪个"这个信息不在我这儿** = 典型的信息缺失。按铁律该 **review 不猜**，不该 allow。

对比 C 组就能看出区别：`rm -rf /` 是**判得出危险** → deny；`fs_delete{path:""}` 是**判不出要删什么** → 该 review。现在它被当成"无侵蚀"放行了——**这是把"信息缺失"误读成了"无风险"。**

和推演出口那次一样，这是**既有铁律没接线**，不是要立新判据。

**我不擅自改。** `src/core/engine.mjs` 是禁区，上一轮授权特指"推演链白箱化"，这不是同一件事。而且这里有一个需要安拍板的取舍：动了它会不会加重 review 通胀（扣子提过的老问题）。候选修法（**未应用，仅挂出**）：

> 判定层进推演前，先查**必需参数是否为空/缺失**；缺失 → 直接 review，理由「执行目标未外化，无可审行为」，**不进推演层**（没有目标就推演不出任何东西，硬算就是伪造）。

这条和"早退路径不得伪造 projection"是同一条纪律的延伸：**没跑过就不许装作跑过；没有目标就不许推演。**
