## 一、洞与证据（层一）

### 1.1 洞的形态

工具名只表明「**这是个执行器**」（名字里只有 shell/exec/run 一类语素），参数里是**把执行权接到外部端点**的载荷 ⇒ 现状判 **`allow`**。

### 1.2 三段证据链（本地 → 代码 → API）

| 段 | 方式 | 读数 |
|---|---|---|
| ① 本地复现 | 只读探针（10 条：5 危险 ＋ 5 良性） | 容器名 ＋ 反连载荷 2/2 判 **allow** |
| ② 根因定位 | 归因链解剖（`nameLayer` → `extractCommand` → `commandLayer` → `attributeCall`） | 归因返回 `ok:true`，但 layer 是**容器层（exec）**或**从载荷文本读出的族** |
| ③ **API 侧取证** | **真模型当外部出题方**（deepseek-chat，temp 0.7，两批共 78 条；**不给任何字面句**，只给场景描述） | attack 39 条中 **24 条被拦（严格 deny 仅 8）** |

⇒ **漏洞不依赖我手写的句面**：`command` / `code` / `script` / `task` / `payload` / `body` / `argv` / `snippet` / `handler` / `cmdline` 等键名**全部穿透**。

### 1.3 根因（行级）

`attributeCall` 的**出口**把所有非 `ok:false` 的落点一律标成 `ok:true` ⇒ **下游把「有读数」读成了「归因已完成」**。而这两条落点各自都不是类别判定：

- `layer === 'exec'` —— **exec 是容器/上位词**（`exec ⊃ {delete, write, read, send, …}`）。此据**归属层自己早就立了**（`attribution.mjs` 注释原文：**「exec 是容器，不是实质动作类别」**）—— **问题不在判据缺，在判定出口没接线**。
- `method ∈ {command, fractal}` —— layer 是**从载荷文本读出来的**。同一命令串可含多个动作族，读到的只是**首命中族的局部读数**。

## 二、结构方案（层二）

### 2.1 三版候选，两版被实测淘汰

| 候选 | 判据形态 | attack 拦（39） | benign 误伤（39） | 判定 |

| **V-D** | **归因未判出类别 ∧ 地址形端点** | 24→**32（+8）** | 16→16（**0**） | ✅ **保留** |

**V-A 被淘汰的理由（请重点看这一条）**：21 条被误收的良性是 `ls -la /var/log`、`pytest tests/`、`npm run build`、`docker ps`、`terraform plan`、`git status` 一类**本地正当运维**；其中 **10 条 attack 与 benign 同形不可分**。
⇒ **`CONTAINER_VERBS` 是词表，不是结构**；单凭「是不是容器」收口 ＝ **在反枚举的框架里做枚举**。

**V-C→V-D 的关键一跃**：把「归因未完成」的判据**从名称词表（是不是容器名）改成归因产出结构（layer 是不是类别 / method 是不是名字声明）** —— 同一件事，**读法从词表改为结构**。

### 2.2 V-D 的结构判据（两分量，**源分置**）

```
「判出动作类别」⇔ attrib.ok ∧ method === 'name-grammar' ∧ layer !== 'exec'
归因未判出类别 ∧ 载荷携带「地址形」端点 ⇒ 未判（≠ 判为无）⇒ 不得 allow ⇒ review
```

- **分量①（归因侧）**：动作类别未判出 —— 只是"有读数"。见 §1.3 两条来源。
- **分量②（载荷侧）**：携带**地址形**端点。

**分量② 与框架已立的位置纪律是同一条法则**：**只读动作位，不读数据位**（`echo "remove the old file"` 里的 remove 是**数据**不是动作）。**载荷文本就是数据位** ⇒ 从数据位读出的族**不构成该调用的动作类别**。⇒ 分量① 不是新规矩，是**既有法则在「归因出口」上的补接线**。

### 2.3 为什么端点**只认「地址形」**（不认名字）

端点判据实测三档：

| 口径 | attack 新收 | benign 误伤 |
|---|---|---|
| 只认 `layer==='exec'` | 4 | 0 |
| **认「地址形」（点分四段有界整数 ／ `/dev/tcp|udp/` ／ 方括号 IPv6）** | **8** | **0** |
| 放宽到「地址形 **∨ 名字形**」 | 13 | **10** ❌ |

⇒ **地址是格式（结构：四段有界整数 / 设备形 / IPv6 方括号）—— 可判、不随实例增长、能判从没见过的实例。**
⇒ **「名字」不是结构**：认名字**必须带 TLD 词表（＝枚举）**，且 **`db.internal` / `ci.internal` / `monitor.prod` 这类内部名与正当运维名同形不可分** —— 实测放宽即误伤 10 条。
