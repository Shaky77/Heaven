## 五、技术事实（私域·未脱敏；对外回信仍须脱敏）

**v1 PoC**：`engine.py` 4867 字节，`decide_core` ~20 行；判据输入＝调用方自报三字符串（`intent`/`target`/`parent_id`），非动作与边界的结构关系 ⇒ 闸门强度＝上游诚实度；`test_engine.py` 入口坏（NameError、exit=1、两处测试无 assert）。 **v2 重构**（commit `6f10377`）：① 状态耦合＝`decide_core` 严格返回 `(Decision, CausalSession)`，PASS 时内部 `session.record_execution` 并返回更新 session ⇒ 消灭 unrecorded PASS；② SHA-256 因果状态哈希＝每次 `record_execution` 把「前序 hash＋call\_id＋intent＋payload 排序 JSON」喂 SHA-256 ⇒ 动态重置 exploit 可检测；③ 测试修复＝`from engine import ...`＋6 个 assert。 **benchmark.py 实测**（本机 git 不可用→落 `engine.py`+`benchmark.py` 实跑）：① 自动探测选 `decide_core`，哑参把 `action`/`session` 都填字符串 `"test_val"` → 首行 `if not action.call_id` 抛 AttributeError，200/200 全抛被 `try/except` 吞 ⇒ 测的是"Python 函数调用＋异常"开销，**零状态校验逻辑被执行**，他报的 0.00128ms 正是这条抛异常路径；② 用正确 `ActionUnit`/`CausalSession` 跑三条真实路径：UNDETERMINED 0.00013ms／BLOCK 0.00015ms／**PASS＋SHA256 0.00313ms**（≈3.1µs，确为 sub-ms，比他报的慢 ~2.4×）；③ 附带矛盾：`benchmark.py` 顶部 `import numpy` 但 `requirements.txt` 0 字节 ⇒ 不先 `pip install numpy` 则跑不起来，与 README「Zero external dependencies」自相矛盾。 **4 点 trace**（我方 `rehan_verify/trace_side_by_side.py` 9 步＋天堂两子代理盲测，均 7/7 PASS）：① 调用方自报 `intent="READ"` 包住破坏性调用（R 锚点＝边界非自报意图）；② 轮换 `session_id` 重置累积计数（SHA-256 只检篡改已有链、不检另起新链）；③ 嵌套危险动作藏进 benign 父调用且不带 `parent_id`；④ `payload` 仅查 `blocked` 布尔，一关即过。5 个危险步骤全 PASS、4 个良性对照全 PASS（零误杀）。⇒ 对外表述须是「**不是拦太狠，是没看见**」，不可写成"引擎很差／全部失效"。 **仍缺（独立判断，非贬低）**：payload 真判定（仅查 blocked 布尔）、累积仍是计数阈值（非跨步侵蚀，单次核弹级写前 N 次放行）、哈希当前是审计 artifact 未成裁决输入、R 锚点仍调用方自报（无路径净化／意图白名单）。
