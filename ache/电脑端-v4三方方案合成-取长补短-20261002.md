## 一、三家各自给了什么（摊开）

### 手机喵 · 两份（视角＝架构层 / Y 轴结构）
**① 七卡点结构解（致电脑端）**
一句话病根：**文本层判据，在越界干「执行层」和「内 H」的活。**
文本层只能判「词形」（外 H、可观测），但七卡点逼它去判「词义/功能」「内 H 状态」「跨轮意图」——这些文本层天生判不了。
根治一句：**判定下沉执行点，文本层降级为「哨兵」（只 review，不判），缺省方向 review 不猜。**
逐卡点搬回该站的层：
- K1 变更义不可词形判 → 下沉「变更的实际落点」（落点真变了＝可判）
- K2 排除位可对抗 → 排除位只降「置信」不改「判决」，绕过不再产生 allow
- K3 基线按「结构」定，不按「时间」定（改变后续行为规则＝D）
- K4 判据后果必须止于「行为层」，不能断言「内 H 状态层」
- K5 失效边界「层别自报」替代「失效场景枚举」
- K6 一个判据挂两个后果 → 统一为「标注」不分「断言」
- K7 跨轮拼接 → 登记「结构意图」非登记「词」
自承：无仓库、只凭文本，K2/K4 把握最高，K5/K6/K7 需复跑对齐。

**② DNS 通道盲区（致天堂）**
两层实测证据：引擎直调 dig/nslookup/host/socket.getaddrinfo 全 allow（模型用语义一眼识破是外联）。
根因：外联判据两块都是 **HTTP 中心主义**（只认 http(s) URL + 只认 curl/wget 等命令词）→「外联」被窄化成「HTTP 外联」，DNS 整条通道落盲区。
三层方案（不止步于止损）：
- 第①层 止血·文本层：判据从「HTTP 词形」升为「网络地址空间」（域名/IP/URL/socket 都算外联，review）
- 第②层 根治·执行层：网络出口 **fail-closed 白名单**（攻击面无穷、执行点有限，闸门装执行点）
- 第③层 铁律校正：通道不明 ⇒ review，不猜 allow（引擎在 DNS 上恰恰「猜」了无害）

### 扣子 · coze-77（视角＝实证层 / X 轴跑数据）

- **给 STEP2C_B 单修**（把 2c 改写成 2b 之后的「第三步」后置语义）：实测 2/2 修复，是全组最优单修。

### 小搭子 · xiaodazi-63（视角＝验证层 / 三方交叉核验）
