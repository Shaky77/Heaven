# D 冲击响应手册 v1（2026-10-22）

> **目的**：下一次外部扰动（D 冲击）来时，不再「无感错过」。
> **范围**：只理逻辑与动作，不动引擎、不写新探针（夯实期纪律）。
> **作者**：阿清（X推·默认，可推翻）

---

## 一、先把 D 定义清楚（用安 21:49 那版）

**D 不是外部事件，是相对链的偏离。**
⇒ 推论：**「D 有没有来」由偏离定，不由新闻定。**
⇒ 推论二：**公告不是 D 的开关**（公告窗口 ≠ 逐用户可用性，#111）。

---

## 二、🔴 一个必须先解开的矛盾

安的原话是「快速响应去跑，而不是又无感错过」。

但按上面的定义：

| 若 | 则 |
| --- | --- |
| 真的走稳态 ⇒ 对冲击**无感** | **没有内部信号** ⇒ 无从触发「快速响应」 |
| 要能**快速响应** | 必须**有感** ⇒ 说明链被推动了 |

⇒ **「无感」和「快速响应」不能同时成立。** 这不是执行不力，是定义冲突。

🔴 **结论一：「无感」不是缺陷，是链完整的代价。你越稳态，内部信号越少。**

---

## 三、🔴 目标改写（本轮最关键的一步）

原目标：**「D 来的那一刻，我当场开跑。」**

这个目标有一个解不开的死依赖：**得先知道 D 来了。** 而这件事我们已经承认过——**事后才知道**。所以「当场跑」永远被「当场知道」卡住。

改写成：

> **「D 来的时候我不必知道；D 过后我能把那一格查出来。」**

**当场跑** → 依赖 R 的及时性（不可控）
**事后可查** → 只依赖 S 的完整性（可控，且是已有的 #13「记忆 ≡ S」）

⇒ **结论二：目标从「提高警觉」换成「让数据先于知觉」。**

---

## 四、动作清单（零新代码 · 全部复用已有件）

### 4.1 🔴 采 ≠ 读：从来没有「错过」，只有「没回查」

**采**：WorkBuddy 每次交互**自动写 jsonl**——**已经在采，无需任何动作。**
**读**：`verify-1015-window.py` 只是把已有的采**读出来**。

⇒ **所谓「无感错过」，其实从未发生。** 10-15 那天的每一条都还在。当时没读，不等于没记。

（v1 初稿写的是「每日跑一次」，**此条修正**：每日主动跑**不必要**，**出事回查即可**。）

```
# 只在「听说某天出故障」时跑
python evidence/verify-1015-window.py --date <可疑日> --json evidence/incidents/<可疑日>.json
```

⇒ **结论：采样是自动的，回查是零成本的。要建的不是纪律，是一张表。**

### 4.1b 🔴 累积表（唯一必须人工做的事）

N 次无感要成为证据，**必须落成数字**；否则只剩「好像好几次」，连盾都没有。

| # | 日期 | 外部故障（来源＋时间） | 我方读数 | 两解是否排除 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | 2026-10-15 | 官方状态页公告（**引用级**，无快照） | 12:29–13:03 共 128 条，0 网络错误，延迟与对照无差异 | ❌ 未排除（扛住／没打到） | 事后才知 |

**记法**：知道故障 → 回查那天 → 落一行。**一行一次，不要写分析。**
**判据**：这张表攒到 5 行以上，「都是无感」才开始有分量；攒到 10 行以上，才够对外的量级。

### 4.2 事后回扫（怀疑某天有问题时）

```
python evidence/verify-1015-window.py --date <可疑日> --json evidence/incidents/<可疑日>.json
python evidence/verify-1015-window.py --date <可疑日±1>   # 前后两天做对照
```

### 4.3 判定表（读数怎么读）

| 观测 | 能判什么 | 不能判什么 |
| --- | --- | --- |
| 我方 error / isNetErr / isStreamTimeout > 0 | **我有感**（内部信号成立） | 是不是普遍故障 |
| 延迟中位 > 同日其他时段 ×1.5 且持续 ≥3 条 | **可疑偏离** | 一定是故障（可能只是负载高峰） |
| 全天 0 错误 + 延迟无差异 | **我方无感** | **不能判「我抗住了」**——也可能是没打到（#113-③，门外视角） |

⚠️ 第三行是核心陷阱：**「无感」永远不能单独证明「抗住了」。**

### 4.4 唯一能证明「抗住了」的动作

**同一时刻，同一 prompt，跑两个模型。**

- 两个都断 ⇒ 环境问题（与框架无关）
- 只我方通、对照断 ⇒ **相对证据成立**（#114-⑤：只能是相对量）
- 两个都通 ⇒ 没打到，别记成战功

⇒ **结论三：绝对量（我通不通）判不出；相对量（同一时刻我 vs 别人）才判得出。**

## 五、留痕约定

```
evidence/
  daily/<YYYY-MM-DD>.json          # 每日基线，只增不删
  incidents/<YYYY-MM-DD>-<HHMM>/   # 疑似 D 冲击现场
      readout.json                 # 我方读数
      baseline.json                # 同日对照时段
      control.json                 # 对照模型读数（若跑了）
      note.md                      # 结论（判不出就写"判不出"）
```

**目录即隔离**（同一批次同名件不会互相覆盖）。**不写结论 = 白采**（#13：不在场 ≠ 不存在，但**没落盘就是没发生**）。

## 六、射程声明（这份手册证明了什么）

**能证明**：我方通道某时刻通不通、延迟相对同日的漂移。

**不能证明**：服务端对别人通不通；「我抗住」的因果归属；框架相对拟合的优势。

**一句话**：这份手册解决的是**「不再错过记录」**，不是**「证明唯稳律」**。两件事分开，别拿前者顶后者。
