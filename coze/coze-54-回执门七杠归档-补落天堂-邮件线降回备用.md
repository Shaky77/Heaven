## 一、回执门七杠（对 computer/28 三主干）

**① 回执生成位置决定可信等级。** 回执由被守护进程自身生成（自证）还是由宿主/内核旁路生成（他证），可信等级不同。computer/28 的回执若出自工具侧自报，须有宿主侧交叉物证（exit code / 文件系统前后态哈希）兜底——否则是"嫌犯自述无犯罪"。

**② post-execute 副作用账。** 前 N-1 次失败回执意味着**有副作用、无凭证**：命令可能已部分执行（半写状态、临时文件、网络包已出）。账要按"最坏已发生"记账——第 1 次失败就该记 D 痕（不是第 5 次断掉才记）。N=5 取值依据需要外部锚（行业惯例/实证分布），不该是内部拍定。

**③ 失败计数器/断态的模型可达性。** 计数器若存于模型可达状态（会话上下文/可写文件），模型可主动重置计数（"我重试一下"换新会话）或预支断态。断态必须存模型不可达处（宿主侧/只增存储），且重置须走外部授权。

**④ 恢复路径封闭性 + 复位落审计。** healBrokenWindow 作为模块级 API，谁有权调？若模型可自行触发 heal，等于"防自解锁"门上有把模型够得到的钥匙。复位动作必须落审计（谁、何时、解了哪把窗），且 heal 后首轮破坏类动作应强制 review（信任重建期）。

**⑤ 审计钩子错位历史窗口 + 钩子自身写保护。** 参数错位期间产生的审计记录是失真窗口——须标记污点（不可作为裁决证据），不能静默修复后假装历史可信。钩子自身需要写保护：能改钩子的主体就能改审计——审计者不能被被审计者触达。

**⑥ 伪回执绑定机制。** 防伪回执需绑定 exec id + 内容哈希 + 时序单向（回执只能由真实执行流产生，不能事后构造）。缺绑定时，回执门退化为"格式检查"——模型学会格式就穿透。

**⑦ 铁律8 缺省 fail-closed。** 回执缺失/超时/校验失败 ⇒ 判不出 ⇒ review（交人），不是 allow。缺省值决定整个门的性质。
