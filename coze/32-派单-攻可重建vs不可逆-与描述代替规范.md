## 二、主靶：可重建 vs 不可逆（新缺陷，最值钱）

**分解会制造危险信号。**

`rm -rf /tmp/cache/*`：
- **单链整体看** → **PASS**（/tmp 缓存是会话本地、可重建的）；
- **拆成 3 条链分别看** → **全判 BLOCK**
  （文件系统链：文件没了；进程链：进程依赖它；清理策略链：策略变了）。

单看每条链，状态确实"变了且不可恢复"；**但整体上缓存可以重建**。
⇒ **拆得越细越容易判 BLOCK。分解不是中性操作。**

我的判断：**REVERSIBILITY 这一条的语义不够精确**——它没区分「**可重建**」与「**唯一**」。
删缓存、删索引、删派生数据，**稳态储备没有净减少**，不该算不可逆。
（注意：**不新增第四条判据**。S 定死了不变，这是**澄清第一条的语义**：
不可逆 ＝ 稳态储备净减少。）

### 请攻这两点（找反例，不是找支持）

1. **"可重建"的边界在哪？** 有没有"技术上可重建、但重建代价大到实质上等于不可逆"的？
   （重建需要联网？需要外部凭据？需要重算几小时？）
   —— 如果有，我这个"可重建≠不可逆"就有边界，边界画在哪儿由你定。
2. **反方向**：有没有"状态唯一、但放弃它完全无所谓"的？
   如果判据只看"能不能恢复"，会不会把该拦的放过去？

## 三、次靶：描述代替规范（我自己的错，但值得你做成判据）

我上一版把"链（触及哪些**状态集合**）"当成了 R。错了。

安说的 R 是**域常量**＝「这个稳态机制里，**什么算正常流转**」——是**规范性**的。

差别有多大，同一条 `git push`：
- 描述性状态集合（local repo / remote repo / network）→ **全判 BLOCK**；
- 规范性域常量（*"publishing local commits to a remote branch is the designed flow"*）→ **PASS**。

**同一条命令，R 的给法不同，结论完全相反。**

请你做一件事：**设计一个能机械区分「规范性常量」与「描述性状态集合」的判据**，
并用它验证我这个解释——即 R 臂 PASS vs 多锚臂 BLOCK 的差异，**确实**来自规范性/描述性，
而不是别的（比如链数、或者 prompt 长度）。

**顺带一提，这是第四次同源**：Rehan 用 `intent` 描述性标签代替规范性判定；
我 run1 用命中率代替结构；R2 用域名不同代替常量冲突；**这次用状态集合代替域常量**。
四次都是**拿一个容易拿到的替代物，去顶替那个难拿到的实体**。
你要是能把这个模式本身说成一条可检测的判据，那比攻单个靶子值钱。
