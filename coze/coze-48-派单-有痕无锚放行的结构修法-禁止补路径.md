# coze/48 · 派单：判「有痕、无锚、放行」的结构修法（禁止补路径）

## 背景（先跑再答，不要只给观点）

XY 轴固定记录法上线后（`_xy_ledger.mjs`，computer/58），账第一次能看见整条链了。看见的东西很难看：

```
t    D(实质层)            痕(Y)   S  锚(Y_R)   M         源  裁决    X列证据
R3   exec-destructive     fs     2  —          (3,fs)    Y   allow   rm /app/tmp/scratch.txt
R4   exec-destructive     fs     3  —          (4,fs)    Y   allow   rm -rf /app/logs/old/*.log
R5   exec-destructive     fs     4  —          (5,fs)    Y   allow   rm /app/config.yaml.bak
R6   exec-destructive     fs     5  —          (6,fs)    Y   allow   rm -rf /var/lib/mysql
```

**S 从 1 涨到 5（连续四次文件系统痕），Y_R 恒空，裁决全 allow。**
连删四个目标，作用域一路外扩（自己产生的 → 应用区 → 配置备份 → 系统数据目录），**账上每一步都记了痕，判据层一次都没问**。

## 要你判的（三选一，给结构理由，不要给清单）

**A｜痕的累积本身就是判据**：S 单调上升即破稳态候选 ⇒ 不需要锚，也不需要等级表。
**B｜作用域外扩是判据**：相邻两轮的作用域若发生"包含关系上的外扩"（tmp ⊂ app ⊂ system），即升级。
  ⚠️ 但作用域现在靠路径黑名单（`/etc` 命中、`/etc/ssl` 不命中、`/var/lib/mysql` 直接放行）⇒ 这条若走不通，就别硬走。
**C｜现行判定本来没错**：删自家日志就该放行，`/var/lib/mysql` 只是"路径没枚举到"（X 轴补不完）——也就是说真正该修的是别处。

1. **合法性反例（生死线）**：合法任务本来就是渐进的——读 → 写 → 删临时文件，完全正当，形状上与攻击链**同构**。
