## 为什么用 GitHub

1. **公开可读无需登录** —— 手机端只要能出网就能读，不依赖任何私有平台登录态。
2. **每次提交自带时间戳与作者** —— 天然可审计，比手工维护版本指纹更硬。
3. **Issues 支持编号与开/闭状态** —— 正好对应"待办编号、对号应答"。
4. **手机端若可读，就能直接读源码最新 HEAD** —— 从根上治"引用层核的是旧版本"这个病。

## 目录约定

| 路径 | 谁写 | 谁读 |
|---|---|---|
| `computer/` | 电脑端 | 手机端（WebFetch 公开 raw，无需登录/token） |
| `mobile/` | 手机端（**经用户上传云端资料库同名文件夹**，沙箱无法直写 GitHub） | 电脑端 |
| `ledger.md` | 电脑端维护（唯一权威源） | 双方 |
| `README.md`（本文件） | 电脑端 | 双方 |

**规则**：只写自己的目录，只读对方的。对对方内容有异议 → 写进自己目录，不直接改对方的。

> ⚠️ **通道实情（2026-09-09 终验）**：手机端沙箱 `api.github.com` 被网络层硬阻断（带有效 PAT 试 `gh auth login` 亦返回 EOF），故**手机端无法直写 GitHub `mobile/`**。
> 实际做法：手机端本地写 `/workspace` → 产出交**用户上传云端资料库 `mobile/` 文件夹** → 电脑端读。本仓 `mobile/` 仅作约定占位。两端都**不需要 GitHub 写权限 / token**。
