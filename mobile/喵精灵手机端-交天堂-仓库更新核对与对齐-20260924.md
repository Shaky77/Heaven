### 2.2 `7a48f3e` 修法：**反转枚举方向**

**病灶（提交说明）**：作用域判据是**枚举**（裸根 / 4 目录 / shadow|passwd），且 `SYS_DELETE` 只匹配顶层目录本身 ⇒ `/etc/nginx`、`/usr/bin/sudo`、`/bin/bash` 全看不见。

**修法**：

> **不列举「哪些目录危险」（开放集，追不完），而列举「哪些域安全」（有限封闭集）。** 与安 09-20 原话同构（「破坏标记有限可封闭、只读命令无限开放」）：此处**用户工作域有限封闭、系统域开放**。 系统域取 **FHS 标准前缀**（有限封闭集，由标准定义、非随手列举）；用户工作域显式排除（避免误伤）。

**落地代码（手机端核过）**：

` ```js const isSystemPath = (p) => { const s = String(p ?? '').replace(/['"]/g, ''); return (/^\/$/.test(s) || FHS_PREFIX.test(s)) && !USER_SPACE.test(s); }; ``` `

**实测**：CN 外部集 S acc **65.2 → 74.2%**、recall **42.9 → 60.0%**，**新增误伤 0**；单测 293/293 零回归。

**⟹ 认知对应**：**锚在"后果"（是否系统域），不锚在"词形"（是否出现过危险词）。**

### 2.3 `453658b`：归因层的"宾语位盲区"——与 `name-grammar` 同族

**提交说明原文（病灶 2）**：

> **宾语位盲区**：`commandLayer` 的破坏名扫全段子串 ⇒ `ls /bin/rm`、`cp /bin/rm /tmp/x` 被误报为"删除动作"（实际动作是列目录/复制）⇒ 危险词当宾语 0/2。 **根因与数据位同族：锚在词形（路径里出现 rm 这个词），不在后果（是否真的删）。**

**⟹ 此即手机端 2026-09-23 发现的 `name-grammar` 病灶，电脑端独立定位到同一根因**（"锚在词形，不在后果"）。

**修法**：**语法槽位**——破坏名只在**谓语位**或**修饰器位**才认，宾语位不认。

**病灶 1（旁路）**：R 格存在"旁路与主链两个源" ⇒ `echo "rm -rf /"` 走旁路命中而主链判 exec，同案两源不一致。**修法：旁路接回主链。**

**病灶 3（格空缺）**：

> **S 格完全空缺**；**D 格退化为累积计数器**；**M 格截断**（出口只回 `{kind,law,reason}`，不返 S 变化量）。 **统一症状 = "格还在，产物里找不到它自己定义要求的东西"。**

**⟹ 此条呼应作者"传导链不可跳跃、不可逆序"**——**格在但产物缺失，等于链上有空环。**
