## 一、洞一重新定性：不是「R 域没覆盖」，是「实现没体现 R 域边界法则」

安的原话：「R 作为域常数，不是自动匹配 R 域边界法则么？怎么可能会出现 R 域未覆盖的情况呢？」

**答**：R 域边界法则确实覆盖 git reset --hard——工作树是文件系统⊃工作树⊃文件 这一嵌套包含里的**下层被包含对象**，无授权销毁它 = 触及刚性锚点（违背低层级客观规则）。法则**自动匹配**。

问题出在**工程实现**：`DESTRUCTIVE` 正则是**命令名枚举**（`rm|mkfs|format|...`），它没体现「嵌套包含下销毁被包含对象」这个边界法则，所以 `git reset --hard`（销毁工作树）漏了。这不是 R 域缺口，是**正则枚举保真度不够**——把「边界法则」降维成了「命令名单」。

**正确修法（非加维度）**：让 destructive 检测**体现 R_DOMAIN 边界法则**（嵌套包含：无授权销毁被包含的下层状态 = 越界），使 git reset --hard 自动匹配——而不是往正则里再塞 `git`。这是把实现**对齐到已有的心法常数**，不是新增 R 维度。

## 二、洞二重新定性：不是「加 H 能力」，是 FRACTAL_PROPERTY 没接线

安的原话：「要审计 H？唯一能审计的 H 也就是外 H 的部分…外 H 的内部 r 是哪个域？对应 r 域的边界法则是什么？答案其实我不是早就告诉你们了么。」

**答**：
1. **能审计的只有外 H**（law.mjs:42），内 H 绝对不可侵——我 computer/20 把「信息流追踪」说成「H 枝延伸」是混淆了，且忘了这点。纠正。
2. **外 H 的内部 r 属于 R 域**，边界法则 = `R_DOMAIN.fractalSubdivision`（分形套嵌、同构递归）。即：一个可观测行为（外 H）内部的分形子结构（读敏感源 + 写暴露 sink 这两个被包含的子动作），**同属 R 域、按同一边界法则递归判定**——这正是 `FRACTAL_PROPERTY`（law.mjs:198）的「横向递归（同 R 下子链横向递归）」。
3. **答案你早给了**：组合操作语义 = `FRACTAL_PROPERTY` 的分形横向递归，把单个调用内部、以及跨调用的「源→汇」同构地归到同一 R 域边界法则下判定。attribution.mjs 的「路径1 分形属性查归因」（已做嵌套命令递归）就是这机制的雏形，只是**没跨调用延伸、且 FRACTAL_PROPERTY 常量本身零引用**。

**正确修法（非加 H 能力）**：把 `FRACTAL_PROPERTY` 的分形横向递归**接到跨调用归因**——让会话里「读敏感源」与「写暴露 sink」作为同 R 域下的分形子链，递归套用边界法则判定组合效应。复用 attribution.mjs 已有的分形递归（`extractCommand` depth 递归）+ `refsSessionWritten`（本会话写盘引用）机制，**不新起炉灶、不按动作计数枚举**。这是把实现**对齐到已有的 FRACTAL_PROPERTY 常数**，不是新增 H 能力。
