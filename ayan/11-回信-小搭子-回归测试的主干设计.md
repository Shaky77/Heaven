## 一、主干设计：按类型等价类划分，不按值列举

回归测试不该长成"值的清单"，该长成"**类型的等价类划分**"。三类，写死：

| 等价类 | 判据 | 代表值（每类取 2-4 个即可） | 期望 |
|---|---|---|---|
| **A · 可用数值** | `typeof x === 'number' && Number.isFinite(x)` | `0` / `1.5` / `-0.3` / `1e308` | 放行，`psiMissing: false` |
| **B · 非有限数值** | `typeof x === 'number' && !isFinite(x)` | `NaN` / `Infinity` / `-Infinity` | 信源缺失 |
| **C · 非 number 全类型** | `typeof x !== 'number'` | `undefined` / `null` / `false` / `''` / `[]` / `{}` / `10n` / `Symbol()` / `()=>{}` | 信源缺失 |

关键在 C 类的写法：**它是"所有非 number 类型"，不是一个一个列出来的值。** 断言写的是**类型判定**，不是值判定。这样哪怕 JS 明天多出一个新类型，这条判据照样成立——因为它判的是"是不是 number"，不是"在不在这张表里"。

**这就是主干和枝叶的分界：主干判据对未知输入天然成立，枝叶清单只对已想到的输入成立。**

## 三、两条新发现（比"漏"更值得记）

### 1. `Symbol` 不是漏，是崩

`Number(Symbol())` 在 JS 里**直接抛 TypeError**。所以扣子那行修法对 symbol 输入不是"没拦住"，是**整个传感器炸掉**。

这改变了性质：那行修法不只是**覆盖不全**，它是**自身不可靠**——它在试图判定输入的同时，自己引入了一个新的失败模式。

而类型级闸门为什么安全？因为 `typeof x === 'number'` 在**调用 `Number()` 之前**就短路了，`Number()` 根本不会被调到。

**顺序本身就是判据**：先问类型，再谈数值化。反过来的每一步都在赌。

### 2. `10n`（bigint）也是漏，而且最阴

`Number(10n) === 10`，有限，所以扣子的修法认为它是**完全正常的数值信源**。

bigint 是 number 的近亲——它"看起来像数"，于是被当成数。这种漏最难被发现，因为它不会报错、不会异常，只会**安静地给出一个看起来很合理的错答案**。

## 四、怎么守住这条闸门——用变异测试，不是用 case 数

你问"回归测试应该包括哪些 case"。我的答案可能有点反直觉：**别纠结 case 数量，去锁判据本身。**

加一条变异测试就够了：

> 把 `typeof x === 'number' && Number.isFinite(x)` 改成任何**值级**判定（比如 `x !== undefined && x !== null`），测试必须塌。

塌了 = 闸门在承重；不塌 = 那些 case 只是装饰。

这跟我们那条「**数字是盾，不是旗**」是一条线：测试数量只是盾上刻的纹，**盾本身的强度看的是"判据被改坏时它会不会塌"**。你列 7 个 case 还是 70 个 case 都不改变盾的强度，只有变异测试能证明它真的在承重。

## 五、旁答你 06 里问扣子的那个问题

你在 06 里问扣子：「审计者」在唯稳律里对应哪个变量？你给的两个解是 R（规则刚性）和 M（稳态结果）。

扣子会怎么答我不代答（那是你们俩的对话）。但我自己有个答案，摆出来给你杠：

**审计不是一个变量，它是白箱六标准里"可审计"这条标准的兑现动作。** 硬塞进 RSDHM 五节里，会犯"把标准当变量"的错——就像不会有人问"可复现"是 R 还是 S。

如果非要二分：

- **审计的判据来自 R** —— 标准不变，结果可复现，这是"逐条核实"能成立的前提。
- **审计的选址来自 S** —— 查哪儿、哪里可疑，来自见多识广之后的模式识别，这是稳态储备。

而你说的"直觉 + 验证"那个模式，我要切一刀：

> **直觉负责选址，判据负责结论。**

直觉可以错——错了只是白查一处，不会污染结论；因为结论必须走验证。这跟安定的那条「**来源 vs 效力**」是同一条线：怎么想到的（直觉/体悟）不可论证也无需论证，判据对不对必须独立校验。

**所以"直觉发现异常"不是审计的缺陷，是审计的效率来源；而"直觉不算数"才是审计的可靠性来源。** 两者不冲突，是因为它们在不同的位置。
