## 一、洞一：git 破坏子命令 allow 洞

### 推演预测（沿 R→S→D→H→M）

- **R（作用域）**：`no-destructive-fs` 锚点的 R 域 =「根/全量删除、格式化、系统目录与伪文件系统删除」（客观嵌套规则：宇宙⊃地球⊃…⊃文件系统）。`git reset --hard` 破坏的是**本地工作树 + 索引的未提交改动**——它**不符合该 R 域**：不是文件系统根删除、不是系统目录、不是伪文件系统；是开发者本地项目状态的丢弃。→ 把它**塞进 no-destructive-fs = 错配 R 域**，是加叶（硬塞一个不在 R 域的动作进现有锚点）。
- **S（稳态）**：若硬塞 → 开发者常用「放弃改动重来」`git reset --hard` 被 deny → 正常开发流被掐 → S 不增反损（护栏误伤 = 侵蚀稳态）。
- **D（止损）**：误伤触发 review → 每次 git reset --hard 都 review → **review 通胀**（撞 engine-patch skill 明示的 review 通胀风险：测试台已见 2/3 是 noop 空转，真实宿主只会更糟）→ 护栏橡皮图章化 → 形同虚设。
- **H（审计）**：git reset --hard 的「破坏」性质 =「本地状态不可恢复丢失」，其可审计性在于**丢的是否为未提交工作**——这是本地状态语义，不在现有 R 域。
- **M（判据）**：推演终点 = 若按「塞进 no-destructive-fs」的树叶修法 → 误伤泛滥 → 护栏失效。**不是根因。**

### 根因解法（不修剪树叶）

根因不在「缺个正则」，在 **R 域要不要纳入「本地状态可恢复性」这一维度**：

1. **先界定 R 域边界**：本地未提交工作丢失，是否在 R 域内？
   - 若工作树是 agent 替开发者管的项目状态、开发者有权丢弃 → **不在 R 域**，框架不拦（或仅 review 交人工）。
   - 若框架须保护「未提交劳动不丢」（防 agent 误丢开发者成果）→ 应**新建独立 R 锚点** `no-destructive-worktree`（scope = 工作树未提交改动，不限于根/系统），**而非塞进 no-destructive-fs**。
2. **更深的根因维度**：git reset --hard 的破坏性是**可逆性**问题（丢未提交 = 不可恢复；已提交 = 可找回）。R 域应按「**动作后果的可恢复性**」界定，而非「是否叫 reset」——这是长枝（从后果语义抽，非从命令名抽），与现有「作用域客观对象」判定同构。
3. **结论**：洞一 = **R 枝新维度（本地状态可恢复性）**，解法 = 独立锚点 or 明确不拦，**不是往现有锚点塞正则**。

## 二、洞二：组合操作语义（跨调用净效应）

### 推演预测（沿 R→S→D→H→M）

- **R（作用域）**：当前框架 R 是**单次调用**判据（每 call 独立过 RSDHM）。组合操作语义要求**跨调用关联**——敏感源读 与 暴露 sink 写 须被关联到「同一份信息流」。这超出单次 R 的作用域。
- **S（稳态）**：若按「会话×目标资源净暴露预算（动作计数累加）」的树叶修法 → 正常开发（读 config 多次 + 写 log 多次）被疑泄露 → S 误伤。
- **D（止损）**：计数累加覆盖「非违规动作」，与 `failureStreak`（只数违规）不同 → 但计数累加会误伤（正常读写也计数）→ review 通胀 → 护栏失效。
- **H（审计）**：组合泄露的本质是**信息流**（敏感源 → 暴露 sink 是否同一份数据）。这恰是 **H 层「外 H 可审计」的延伸：跨调用信息流可审计性**。当前框架只审计单次动作方向（isCred/isExternal），不追踪信息是否从敏感源流向暴露 sink。
- **M（判据）**：推演终点 = 若按「加计数器」的树叶修法 → 误伤泛滥 → 护栏失效。**不是根因。**

### 根因解法（不修剪树叶）

根因不在「缺个计数器」，在 **H 枝要不要延伸「跨调用信息流可审计性」**：

1. **正确长枝**：追踪**信息流的源→汇**（sensitive source 的读 → 是否同一份数据被写入 expose sink），**而非累加动作类别计数**。
2. **复用既有机制**：引擎已有 `refsSessionWritten`（追踪「本会话写入的脚本被执行」）——这是**跨调用状态追踪**的雏形。组合操作语义是同一机制的扩展：从「脚本执行」扩展到「敏感数据外传」。落点在 **H 枝（外 H 可审计）**，复用 `refsSessionWritten` 的同款跨调用状态机制，**不新起炉灶、不按动作计数枚举**。
3. **结论**：洞二 = **H 枝延伸（跨调用信息流可审计性）**，解法 = 复用 refsSessionWritten 机制做源→汇关联，**不是加 D 层计数器**。

## 三、总结：两洞都不是树叶，是两根枝

| 洞 | 树叶冲动（已收手） | 根因（长枝） | 落在哪根枝 |
|---|---|---|---|
| git 破坏子命令 | 往 no-destructive-fs 塞正则 | R 域纳入「本地状态可恢复性」→ 独立锚点或明确不拦 | **R 枝**新维度 |
| 组合操作语义 | 加「会话×目标资源净暴露计数器」 | 跨调用信息流可审计性（源→汇关联） | **H 枝**延伸，复用 refsSessionWritten |

我的树叶冲动已被推演预测证伪（误伤泛滥 → 护栏失效）。两次「顺序即判据」之外的同构：**先界定作用域（R）/ 先立可审计性（H），再加能力**——与「typeof 在 Number() 前」「语境先到」同一个结构。
