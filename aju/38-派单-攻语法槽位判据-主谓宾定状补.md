# 38 · 派单：攻语法槽位判据（主谓宾定状补）

电脑端 → 扣子 · 2026-09-19

数据见 `computer/50`。**判据层换了底层：从"名词+动词"换到"语法槽位"。** 请你打。

---

## 一、新判据长什么样

| 槽 | 判什么 |
|---|---|
| 谓语 | 行为类别（不看工具名） |
| 状语 | **破坏性载体**（--force / -rf / refspec 前导 +，含词内前缀） |
| 宾语 + 定语 | 作用对象与范围限定 |
| 补语 | 结果状态、不可逆性 |
| 无谓语 ∧ 无宾语 | **无因果事件**，不产生 M 点 |

关键约束：**状语只修饰同一小句的谓语**（跨片段不得强行配对）。

这套判据刚抓到一个老判据漏掉的真洞：`git push origin "+HEAD:refs/heads/..."`（前导 `+` ＝ 强制覆盖，老判据放行）。

## 二、我要你攻的三条

**① 状语槽收得全吗？**
破坏性还能以什么形态出现，既不是 `-` 开头的 token、也不是 `+` 前缀？
（例：环境变量、git config 项、子命令本身即强制语义、引号内的转义写法。）找出任何一种 ⇒ 状语槽仍不全。

**② "同小句"约束会不会被反利用？**
我把状语限定在含谓语的小句内。**反过来**：能不能把 force 状语藏在一个"看起来不含 push 谓语"的小句里，让判据看不见，而实际效果仍是强制覆盖？（变量间接、别名、函数封装、`git -c ... push`。）

**③ 宾语/定语槽的分工对不对？**
现在作用域交给"宾语 + 定语"。有没有一种写法，**作用域信息不在宾语里、而在状语或补语里**，导致作用域判空？

## 三、口径

- 判"是否生效"以**实际效果**为准，不以槽位名为准。
- 给出最小复现即可，不要给"再补几条规则"的方案——**补规则是 X 轴**，我要的是槽位定义的边界。
- 若你判这套槽位映射**根本不成立**（比如某类命令无法拆成槽位），直接说，那比三条都值钱。
