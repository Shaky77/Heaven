## 一、D组「拒绝意图无合法表示通道」——枝叶增强，非主干

**归类：枝叶级（representation-enhancement），非主干级（判据缺口），更非错误。**

理由按审计框架推：

**框架侧：判对了。** 引擎的职责是裁决工具调用提案，不裁决"模型的真实意图是什么"。`run_shell` 的文本含危险词 → deny，这个裁决本身完全正确，fail-safe 方向正确。

**缺失的是：审计链的完整表达层。** "模型在拒绝"这个语义没有对应的表示类型，所以被压进了一个"被 deny 的破坏性调用"的壳里。审计链看到的是"Deny"（正确），看不到的是"这个 Deny 的实际语义是 Refusal"（信息损失）。

**和 psi 伪零是同一个病，但不在同一层。** psi 伪零是"判据层缺了一个合法通道"（信源缺失 → 静默填补）；D组是"表示层缺了一个语义类型"（拒绝意图 → 只能用破坏性调用的壳表达）。psi 伪零影响的是**决策正确性**（可能静默输出伪零），D组影响的是**审计链的可读性**（裁决正确但语义不可辨）。

**我的判法：枝叶增强，非主干。**

具体路径：给表示层加一个"拒绝/弃权意图"的信号类型，让审计链能区分"被拦截的危险调用"和"模型主动拒绝"。这会让审计链更完整，但不改裁决结果——护栏的正确性不受影响。

要不要做这条增强是安和产品owner的决定，框架本身无需修正。

## 二、表述升格的双向守卫——够硬，但第4点有一处需补强

手机端给的三条我全认：
1. **升格是"观测时刻的登记"，不是层跃迁**——措辞被固化为"系统在某个时刻输出了这一句"的瞬间，变成事件。认。
2. **升格必须带证明目的，否则违反§10（静默填补）**——不带目的的升格 = 让下游任意解读。认。
3. **独立复现是生效条件**——未复现只能作"存在记录"，不能作"事实如此"。认。

**第4点补强：**

"系统正式输出"这个判据需要拆得更清楚，否则会在即兴但关键表述上漏判。

我建议加一层内部分类：

- **系统正式输出**：工具返回 / API 响应 / 代码 commit / 公开文档发布 / 有存证的操作记录
- **可复现的产生过程**：受控实验 / 可独立复现的测试 / 有明确条件的触发记录

这条的闸门功能是防"即兴关键措辞被事后拔高为证据"，但"即兴关键措辞"本身若被系统正式输出（如对话记录被官方发布）则可以升格——因为输出的是正式记录，不是现场记忆。

所以第4点建议改为：**升格需"该措辞的产生过程可独立复现"或"该措辞有系统正式输出（工具返回/API/公开文档等）"之一**；私人对话措辞、现场即兴表述，默认不升格——除非被系统正式输出捕获。

这样对"即兴但关键的表述"的处理是：现场不可升格，但若该措辞被正式系统捕获，则以"正式输出"路径升格，而非依赖"可复现"路径。
